# Public Safety & Confidentiality Guidelines

This repository is a **public learning and experimentation space** for studying reliable AI systems, agent runtimes, and AI infrastructure.

All content in this repository is created with strict adherence to professional confidentiality and intellectual property standards.

---

## Core Principles

1. **No employer or proprietary information**
2. **No customer or sensitive data**
3. **No reproduction of internal systems**
4. **All examples are synthetic, public, or original**
5. **Learning is based on first principles, not replication**

---

## What is NOT Allowed

The following must **never** appear in this repository:

### Employer / Company Information
- Any code, documentation, designs, or other artifacts created for a current or former employer
- Internal system designs, architecture diagrams, or workflows
- Internal service names, APIs, or infrastructure details
- Operational practices that are not publicly documented

### Data & Metrics
- Customer data or logs (even anonymized)
- Real production metrics or internal performance numbers
- Internal datasets or benchmarks
- Proprietary prompts or workflows

### Documentation & Knowledge
- Internal documents, wikis, runbooks, or incident reports
- Private discussions or design decisions
- Screenshots of internal tools or dashboards

---

## What IS Allowed

The repository only uses:

### Code & Systems
- Original code written specifically for this repository
- Re-implementations based on public concepts (not internal systems)
- Open-source libraries and frameworks

### Data & Inputs
- Public datasets
- Synthetic or generated data
- Purpose-built demo scenarios
- Public repositories for experimentation

### Concepts & Knowledge
- Public blog posts, papers, and documentation
- First-principles reasoning
- Personal interpretations and learnings

---

## Public-Safe Design Approach

All systems in this repository follow:

- **First-principles design**  
  (No copying internal implementations)

- **Simplified scope**  
  (Focus on concepts, not production parity)

- **Explicit assumptions**  
  (All tradeoffs and simplifications documented)

- **Synthetic scenarios**  
  (All demos use invented or public data)

---

## Example Boundaries

### ✅ Acceptable
- “Designing a retry system for unreliable APIs”
- “Building a durable workflow with checkpoints and replay”
- “Simulating agent tool failures and recovery strategies”
- “Comparing model routing strategies using mock providers”

### ❌ Not Acceptable
- Recreating a current or former employer’s internal system architecture
- Using non-public logs, incidents, or failure cases
- Describing non-public service interactions or operational workflows
- Sharing unpublished production metrics, benchmarks, or system behavior

---

## Attribution & Sources

- All external ideas are attributed to public sources
- Open-source code usage follows license requirements
- No proprietary information is included, paraphrased, transformed, or used as
a source for published designs or implementations

---

## Personal Responsibility

This repository reflects **personal learning only** and does not represent any employer.

All content is:
- created independently using personal accounts, equipment, and repositories
- based only on public sources, appropriately licensed open-source material,
  synthetic data, or original work
- reviewed for confidentiality, attribution, and accidental secret exposure
  before publication

---

## When in Doubt

If any content feels close to internal knowledge or experience:

→ **Do not include it**

Instead:
- abstract the idea
- simplify the scenario
- recreate from first principles
- or omit entirely

---

## Summary

This repository is intended to demonstrate:
- engineering thinking
- system design skills
- practical experimentation

—not access to proprietary systems.

Maintaining this boundary is essential for:
- professional integrity
- legal safety
- long-term credibility
